## Главная идея: Как работает VFS в памяти?

По заданию нам строго запрещено распаковывать ZIP-архив на жесткий диск. Поэтому эмулятор делает хитрый трюк:
1. При старте он открывает ZIP-файл.
2. Пробегается по всем путям внутри него.
3. Переносит всю структуру папок и содержимое файлов в обычный Python-словарь (`self.vfs_files`).
4. В итоге жесткий диск больше вообще не трогается. Когда мы пишем `mkdir` или `chown`, мы просто добавляем новые записи в этот словарь прямо в оперативке.


## Разбор класса TerminalEmulator и его функций

Вся программа живет внутри одного большого класса `TerminalEmulator`. Вот подробное описание каждого метода, из которых он состоит, включая внутренние хелперы, добавленные для оптимизации цикломатической сложности:

### 1. Метод `__init__(self, root, vfs_path, log_path, script_path)`
Это конструктор класса. Он срабатывает в самый первый миг запуска программы.
* Что делает: 
  * Настраивает главное окно `tkinter` (задает размеры на основе константы `WINDOW_GEOMETRY` и меняет заголовок окна на имя нашего ZIP-архива).
  * Создает текстовое поле терминала, используя глобальные константы стилей (`BG_COLOR`, `FG_COLOR`, `FONT_FAMILY`, `FONT_SIZE`).
  * Вызывает функцию загрузки файловой системы (`load_vfs`) и функцию автоматического запуска сценариев (`load_and_run_script`).
  * Привязывает кнопки клавиатуры и защищает поле ввода через метод `handle_keypress`.

### 2. Функция `load_vfs(self)`
Отвечает за первичное подключение нашей виртуальной файловой системы.
* Как работает: 
  * Сначала проверяет, существует ли вообще ZIP-файл на компьютере и является ли он валидным архивом. Если нет, выведет на экран ошибку: `VFS Error`.
  * Если всё хорошо, она инициализирует корневой каталог в памяти по константе `ROOT_DIR` и открывает архив через встроенный модуль `zipfile`.
  * Чтобы не превышать лимит цикломатической сложности (правило <= 10), перебор элементов полностью делегирован выделенному методу `_process_zip_entry`.

### 2.1 Вспомогательный метод `_process_zip_entry(self, archive, name)`
*   **Зачем добавлен:** Изолирует логику разбора путей внутри ZIP-архива для снижения цикломатической сложности метода `load_vfs`.
*   **Как работает:** Нормализует пути, заменяя системные слеши на UNIX-слеши. Проверяет, является ли текущий элемент файлом или папкой. Для файлов считывает текстовое содержимое в кодировке `utf-8` (бинарные данные заменяет безопасной заглушкой `BINARY_DATA_STR`), после чего заносит готовую структуру в оперативную память (`self.vfs_files`).

### 3. Функция `handle_keypress(self, event)`
Она следит за тем, что именно вы нажимаете на клавиатуре внутри окна.
*   **Защита от стирания:** Если вы нажимаете `BackSpace`, функция строго сравнивает координаты курсора через `self.terminal.compare` и позицию `self.input_start_index`. Она использует условию **«меньше либо равно» (`<=`)**, что полностью блокирует стирание букв самого промпта (строки `user@emulator:/$ `) при любых сценариях и быстрых нажатиях.
*   **Нажатие Enter:** Как только вы нажимаете `Return` (Enter), функция берет написанный вами текст, переносит строку и отправляет его в главный обработчик команд.

### 4. Функция `_resolve_path(self, target_path)`
Это внутренний навигатор нашего эмулятора. Он перевод относительные пути в абсолютные.
*   **Как работает:** Склеивает текущий путь с тем, что ввёл пользователь, разбивает строку по элементам и обрабатывает точки: если видит `.`, то просто пропускает её, а если видит `..`, то удаляет последний элемент из пути (шаг назад). На выходе получается чистый и правильный UNIX-путь.

### 5. Функция `log_event(self, command_str, error_msg="")`
Это бортовой самописец эмулятора. Она фиксирует абсолютно все ваши действия в файле формата CSV.
*   **Как работает:** Открывает файл лога, если его нет — создаёт и пишет заголовки колонок (`Timestamp, Command, Error Message`). При каждом вызове любой команды она дописывает туда новую строчку с текущим временем, текстом команды и текстом ошибки (если она была).

### 6. Функция `load_and_run_script(self)`
Отвечает за подготовку автоматического теста при запуске программы. Читает текстовый файл со скриптом построчно, удаляет пустые строки и пробелы по краям, после чего сохраняет готовый список команд в массив `self.script_commands` и передает управление таймеру.

### 7. Функция `execute_next_script_command(self, index)`
Отвечает за симуляцию «автопилота». Берет команду из списка по её номеру, печатает её текст на экран, а затем вызывает метод `execute_command`, будто эту команду ввёл живой человек. После этого делает паузу в 800 миллисекунд (через метод `root.after`) и рекурсивно вызывает саму себя для выполнения следующей строки.

### 8. Главная функция `execute_command(self, input_string, from_script=False)`
Это сердце и главный диспетчер команд нашего терминала.
*   **Как работает парсер:** Метод `.split()` разделяет ввод по пробелам. Первый элемент массива становится командой (`command`), а все последующие — списком аргументов (`args`).
*   **Таблица перенаправления:** Для снижения цикломатической сложности условный оператор `if-elif-else` был полностью заменен на лаконичный **словарь команд (`commands`)**. Каждой строке-команде сопоставлена лямбда-функция её вызова. Если команда найдена в словаре, она выполняется, если нет — выводится стандартное сообщение `sh: command not found`.


## 💻 Внутреннее устройство UNIX-команд эмулятора

Внутри класса прописана строгая логика для каждой утилиты. Они взаимодействуют со словарем в оперативной памяти с использованием глобальных констант (`TYPE_DIR`, `TYPE_FILE`, `DEFAULT_OWNER`), полностью исключая использование «магических литералов»:

*   **`exit`**
    Проверяет аргументы. Если передан нецифровой аргумент (путем проверки корректности индекса в массиве `args`) или их слишком много, она ругнется в лог. В случае успеха вызывает встроенный метод `self.root.quit()`, который мгновенно и чисто закрывает графическое окно эмулятора.
*   **`pwd`**
    Просто берет строку из переменной `self.current_path`, в которой хранится наш текущий виртуальный адрес в памяти, и распечатывает её на экране.
*   **`uname`**
    Имитирует выдачу информации о ядре ОС. Поддерживает ключи `-a` и `-r`.
*   **`cd`**
    Принимает целевой путь, прогоняет его через `_resolve_path`. Если полученный путь существует в словаре `self.vfs_files` и у него тип `TYPE_DIR`, то переменная `self.current_path` обновляется.
*   **`ls`**
    Сканирует ключи словаря `self.vfs_files` и ищет элементы, у которых родительский адрес совпадает с текущим. Если передан флаг `-a`, принудительно добавляет в массив элементы `.` и `..`. Для минимизации сложности логика сбора данных вынесена в отдельный метод `_collect_ls_items`.
    *   **Вспомогательный метод `_collect_ls_items(self, target_dir, use_long)`:** Обходит ключи VFS, фильтрует их по совпадению с целевой директорией и, если активен флаг `-l`, вытаскивает из словаря значение владельца (`owner`) и тип элемента (`d` или `-`), формируя длинную строковую маску по стандарту POSIX.
*   **`tail`**
    Парсит флаг `-n`. Идет в словарь VFS, проверяет, что цель имеет тип `TYPE_FILE`, забирает текстовое содержимое через `["content"]`, разбивает его на строки с помощью `.splitlines()` и выводит на экран терминала строго последние N строк (по умолчанию 10). Для снижения сложности запутаный парсинг флага `-n` вынесен в отдельный метод.
    *   **Вспомогательный метод `_extract_tail_val(self, args, i)`:** Изолирует логику определения слитного (например, `-n5`) или раздельного (например, `-n 5`) написания флага. Проверяет значение на `isdigit()`, высчитывает правильное смещение индекса для цикла `while` и возвращает результат или текст ошибки.
*   **`mkdir`**
    Создает новую папку. Проверяет через `_resolve_path`, существует ли родительский путь и свободен ли целевой адрес. В случае успеха добавляет в словарь `self.vfs_files` новый ключ с типом `TYPE_DIR` и владельцем `DEFAULT_OWNER`. Исходный ZIP-архив на диске при этом не изменяется.
*   **`chown`**
    Принимает имя нового пользователя и путь к элементу. Находит этот путь в словаре `self.vfs_files` и перезаписывает текстовое поле: `["owner"] = new_owner`. Результат смены владельца можно сразу же наглядно проверить в эмуляторе с помощью команды `ls -l`.


## Документация поддерживаемых UNIX-команд

Каждая команда адаптирована под требования стандартов POSIX и обрабатывает ошибки параметров. Вся логика вынесена в изолированные методы:

*   `pwd` - Выводит текущий абсолютный путь внутри памяти VFS (`self.current_path`).
*   `uname` - Системная утилита. Поддерживает ключи `-a` (полная информация о виртуальной системе) и `-r` (релиз ядра).
*   `cd [путь]` - Перемещает пользователя по папкам VFS. Поддерживает относительные пути, а также переходы `.` (текущая) и `..` (родительская папка).
*   `ls [путь]` - Выводит список элементов. Поддерживает склеенные флаги:
    *   `-a` - Отображает скрытые служебные ссылки `.` и `..`.
    *   `-l` - Включает длинный режим вывода с указанием типа (`d`/`-`) и текущего владельца.
*   `tail [-n число] [файл]` - Читает текстовое содержимое файла из VFS и выводит последние N строк (по умолчанию 10).
*   `mkdir [путь]` - Создает новую пустую папку strictly в оперативной памяти VFS, присваивая ей владельца `root`.
*   `chown [владелец] [путь]` - Модифицирует поле `"owner"` у папки или файла внутри словаря оперативки.
*   `exit` - Безопасно завершает работу графического интерфейса. Принимает числовой код возврата.

## Спецификация формата логов CSV

История вызовов автоматически записывается в лог-файл, заданный через аргумент `--log`. Файл содержит три строго структурированные колонки:

| Имя колонки | Тип данных | Описание | Пример значения |
| :--- | :--- | :--- | :--- |
| Timestamp | Строка (ГГГГ-ММ-ДД ЧЧ:ММ:СС) | Точная дата и время фиксации события. | `2026-09-30 23:45:12` |
| Command | Строка | Полная команда, которую ввел пользователь. | `mkdir /home/docs` |
| Error Message | Строка | Текст возникшей ошибки. Пусто, если команда успешна. | `sh: cd: missing: No such file` |

## Интерактивные тест-кейсы (Сценарий автоматизации)

Для полной проверки функционала в папке `tests/` подготовлен стартовый скрипт `start_script.txt`. Ниже приведена таблица шагов, демонстрирующая штатную работу и отработку ошибок:

| № шага | Команда скрипта | Ожидаемый результат в терминале | Что проверяется |
| :---: | :--- | :--- | :--- |
| 1 | `pwd` | `/` | Вывод корня VFS при старте. |
| 2 | `uname -a` | `PythonVFSOS 1.0.0 Stage-5 x86_64...` | Работа флагов uname. |
| 3 | `ls -la` | Список файлов, включая `.` и `..` с владельцами | Чтение структуры ZIP в памяти. |
| 4 | `mkdir new_dir` | *(Пустая строка — команда успешна)* | Создание каталога в памяти. |
| 5 | `chown admin new_dir` | *(Пустая строка — команда успешна)* | Смена владельца в словаре VFS. |
| 6 | `ls -l` | Отобразится папка `new_dir` с владельцем `admin` | Взаимодействие mkdir, chown и ls. |
| 7 | `cd missing_folder` | `sh: cd: missing_folder: No such file...` | Ошибка: Переход в скрытый объект. |
| 8 | `tail -n 2 note.txt` | Вывод ровно 2 последних строк файла | Валидация работы tail с текстом. |
| 9 | `exit` | Графическое окно приложения закрывается | Чистый выход из Tkinter. |
